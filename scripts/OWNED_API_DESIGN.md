# Portable owned API qualification: source draft

The portable source implementation is now staged for review after the benchmark
timing hold. It is not a claim of native/API success. No support closure was
copied during that hold. The generic `scripts/check_api.py` protocol checker
stays unchanged. The owned adapter is default-dry; its runtime admission refuses
unfinished complete-tree pins or missing fresh build/config evidence.

## Intended command

Use `scripts/check_owned_api.py` with default-dry behavior. An eventual `--run`
will require a recipient-created private loopback config, explicit completed
BUILD/config/image/runtime-manifest byte pins, the public synthetic long prompt,
its exact answer, and a new exclusive output directory under `.work`.
Loopback qualification uses `127.0.0.1:18080`. It never stops an existing listener,
model, service or tunnel. Credentials remain inside the private config and are
never supplied as CLI arguments or included in source/output.

The recipient must complete native and cancellation gates first. The adapter
does not promote a default or manage production configuration.

## Small source closure

Port the reviewed owner controller and candidate-admission module, plus the two
creation-capability modules. Reuse the existing portable benchmark's
`job_support`, `owned_windows` and `identity_support` modules. This should add
well below 150KiB of source; no native binary, model payload or raw runtime log is
required. Stage this closure only after the timing hold is released.

Preserve the exact validated ownership and protocol functions. Changes belong
only in portable paths and honest new build/runtime source admission. Private
workstation paths, user names, credentials, hostnames, old binary pins and old
private report dependencies must not appear in the portable implementation.
Keep explicit source inverses and source pins for the adaptation.

## Fresh provenance contract

The new build schema is `fresh-portable-v027-V6b-native-build-v1`. Its final actual
fields must be bound before an executable adapter is frozen; do not accept an old
portable-build schema by relabeling it. Required evidence includes:

- Successful fresh compilation/link, exact EXE path and SHA, and complete source
  checkout verification before and after compilation.
- The actual four raw native source pins, full source closure digest/count and
  source7994 reference, plus the exact fresh fifteen-file GGML overlay closure.
- Actual CUDA13.2/toolchain and prospective DLL paths. Read back both loaded
  cuBLAS paths through the retained native capability before inference.
- `pins/api-runtime-overlays.json` and the complete027 runtime assembled from its
  pinned public source archive plus the retained twelve UI assets. This is
  separate from the old frontend60 held fixed by the native Q/Stop benchmark.

The config may use explicit `server_runtime` and its reviewed manifest SHA so
native `cwd` stays unchanged. Validate the runtime's complete dependency/source
closure. Use a new private sibling initial66 routing profile; never overwrite a
learned or production profile.

## Exact ownership and shutdown

Retain suspended frontend creation, attachment and held identity before resume.
The native creator offers its creation handle through the existing authenticated
HMAC/nonce protocol. The parent duplicates only the bounded read capability,
validates actual kernel PID/image/creation time/owned-Job membership and
acknowledges before native resume. No DACL, privileges, global PID discovery or
native-PID reopen is permitted.

Retain one native constructor attempt, launch attestation for the actual raw
config/argv, pre-inference identity and loaded-DLL readback, and the same sole
held native after all API checks. Disable bytecode writes in the copied runtime.
Close frontend stdin for owner-EOF shutdown. Require actual held native exit0
and Jobempty before canonical V3 finish. Frontend owner-pipe130 is separate from
native0. Any live forced termination is failed qualification; empty-Job final
cleanup remains ordinary bookkeeping.

## Exact API contract

Invoke the unchanged strict public protocol checker in the owning process. After
read-only health/auth checks, FIRST inference must be the same public synthetic
near1M body (SHA `6c4f575406cf9303355867354ced548d7c4789830ff6f817ae1f8de83fd17c2a`)
and exact six-digit answer `828639` (SHA
`93280b15904343560264c3cc4b564ccab82097833751482d454e11af71e16050`).
Use FIRST-only `high-budget256`: named high/native effort75, token budget256 and
max_tokens1024. Actual historical API05 usage was999797 input/64 completion/cache0;
the new run must measure its own usage and prove near1M uncached input. Those
historical counts are not inherited results or a new token-count oracle.

After the timing hold, prepare the body with
`python scripts/prepare_api_prompt.py --prepare`. It imports the existing
`prepare_inputs.long_prompt_text`, encodes UTF8 and writes an exclusive binary
file under `.work`. It must match3,434,819 bytes and the fixed6c4f hash before any
file is written. Do not write the text through a Windows text-mode stream:
newline conversion changes the input hash. This preparation performs no
tokenization, model execution or API request.

Keep exact literal answer, natural stop, one terminal DONE, strict usage and cache0
assertions. Keep short natural arithmetic, complete SSE, OpenAI/Anthropic forced
synthetic tools without execution, active-content disconnect, idle and subsequent
natural recovery checks unchanged. No replay, retry, cancellation race waiver,
format regrade or tool execution is allowed. A generic HTTP pass alone does not
provide kernel-native identity or natural native shutdown proof.
